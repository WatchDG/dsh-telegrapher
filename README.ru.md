# dsh-telegrapher

[![CI](https://github.com/WatchDG/dsh-telegrapher/actions/workflows/ci.yml/badge.svg)](https://github.com/WatchDG/dsh-telegrapher/actions/workflows/ci.yml)
[![License: Apache-2.0](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)

[English](README.md) | **Русский**

Экономия токенов «телеграфист» для [DeepSeek Harness](https://www.deepseek.com/en/harness/):
правила в системном промпте сокращают токены ответа и обдумывания, а слой
измерений считает цену каждого правила на сессиях, реально сохранённых этим
хостом, — токенизатором [tiktoken](https://github.com/openai/tiktoken).

Плагин не обещает экономию. Он добавляет правила и измеряет две вещи: сколько
токенов каждое правило сэкономило бы на реальных ответах (потенциал) и стали ли
сессии с правилами тратить меньше токенов на шаг, чем сессии без них (эмпирика).
Правило, которое данные опровергают, получает в журнале вердикт, и это
опровержение видно на странице настроек.

## Что делает плагин

### 1. Правила в промпте

Одна секция системного промпта `telegrapher:rules`, собранная из каталога правил
по выбранному режиму:

- **lean** (по умолчанию) — языковая политика плюс самые ценные правила для
  ответа, инструментов и обдумывания, 437 токенов на запрос в этом каталоге;
- **full** — все измеряемые правила плюс заголовки разделов, 903 токена;
- **auto** — базовые защиты плюс только те правила, чья измеренная окупаемость
  на сессиях профиля `payback >= 1×` (до первого скана работает как `lean`);
- **off** — секции нет.

Правила закрывают три стока, за которые платит сессия разработки: аргументы
инструментов (минимальный якорь правки, правка вместо повторной записи файла,
`replace_all`, префикс `cd`), обдумывание (без повторного вывода, без пересказа
плана, без пересказа результата инструмента) и прозу (ответ сразу, без итогового
блока, ссылка вместо повторной цитаты, без наполнителей). Защита сути остаётся
в любом режиме: код, пути, команды, идентификаторы, строки ошибок и числа не
сжимаются.

### Языковая политика

Язык пользователя там, где пользователь читает, английский — везде остальное.
Первые две строки секции фиксируют это:

- итоговый ответ, план на утверждение и вопрос с вариантами ответа пишутся на
  языке пользователя;
- обдумывание, вызовы инструментов и их описания, статусные строки и внутренние
  заметки — на английском.

Полная таблица, измеренная цена двух языков и пограничные случаи —
в [docs/language.md](docs/language.md).

Секция регистрируется при загрузке плагина; `mode: off` при загрузке убирает её
полностью, смена режима позже пересобирает текст.

### 2. Измеренный отчёт

`Settings → Telegrapher` и инструмент `telegrapher` читают одни и те же числа из
сохранённых сессий через сервис хоста `sessionQuery`:

- токены ответа по стокам — аргументы инструментов, обдумывание, текст ответа —
  с распределением по BPE-массе реально написанного вывода;
- главные инструменты по стоимости аргументов;
- по каждому правилу — число случаев и токены: правило применяется к реальным
  ответам, разница считается tiktoken;
- по каждой сессии — модель, пресет и признак того, была ли секция в промпте.

### 3. Журнал гипотез

Каждое правило — утверждение. Журнал хранит утверждение, доказательства, размер
выборки и вердикт:

| Вердикт | Значение |
|---|---|
| `supported` | правка экономит не меньше токена на случай, минимум в трёх сессиях |
| `refuted` | правка не дала экономии, либо сессии с правилами стали хуже |
| `inconclusive` | измерено, но ниже порога поддержки |
| `unmeasured` | в просканированном корпусе слишком мало случаев |

Для каждого отрисованного правила считается цена его собственной строки:
`payback` — измеренная экономия на сессию, делённая на токены строки. Правило
ниже `1×` видно как строка, которая пока не окупается.

Две эмпирические гипотезы считаются, когда корпус позволяет: H1 (токены ответа
на шаг ассистента) и H2 (токены рассуждений на шаг). Сравнение берёт сессии одной
модели, минимум по пять сообщений ассистента, минимум по три сессии в группе, и
даёт 95%-й бутстрэп-интервал. Это наблюдательное сравнение, и журнал это
проговаривает.

В журнале есть и контрольные замеры — ходы, которые выглядят как экономия, но ею
не являются, — чтобы метод мог опровергнуть их на этом корпусе, а не доверять
утверждению. Удаление пустых строк между пунктами списка — как раз такой
контроль: измерено как нулевая экономия.

## Требования

| Требование | Подробности |
|---|---|
| [DeepSeek Harness](https://www.deepseek.com/en/harness/) | 0.2.x (проверено на 0.2.1-rc.2). Плагин использует `systemPrompt`, `sessionQuery` (анализ), `sessionPersistence` (ограничение размера), `webServer` и `tools`. |
| Node.js | 20 или новее для самого плагина. |
| Python 3 + [tiktoken](https://github.com/openai/tiktoken) | Необязательно. Без него правила работают, а все числа помечаются как оценка. |

### Установка tiktoken

```bash
py -3 -m pip install tiktoken==0.13.0     # Windows
python3 -m pip install tiktoken==0.13.0  # macOS / Linux
```

Проверьте интерпретатор, который плагин найдёт в `PATH`:

```bash
py -3 -c "import tiktoken; print(tiktoken.__version__)"
```

Плагин запускает интерпретатор лениво, держит его живым всё время работы хоста и
останавливает при выгрузке. Поле `python` в конфигурации задаёт путь, если
интерпретатора нет в `PATH`.

## Установка в DeepSeek Harness

Плагин — бандл текущего профиля DSH, поэтому действует на все сессии профиля.

1. Откройте страницу **Plugins** в боковой панели DSH.
2. Выберите **Add plugin** / **Install bundle**, укажите этот каталог (тот, где
   лежит `package.json`), и подтвердите.
3. Убедитесь, что **Telegrapher Token Economy** включён в списке плагинов.

То же самое агент может сделать инструментом `plugin_manager` с
`action: install_bundle` и абсолютным путём к каталогу. DSH записывает
`link:`-зависимость на каталог, поэтому после обновления файлов плагина
перезапустите DSH, чтобы Host загрузил JavaScript заново.

## Секция по умолчанию

`mode: lean` отрисовывает ровно это (437 токенов в `o200k_base`):

```text
## Token economy (telegrapher)

These rules govern the text you write and never override correctness.
- Everything the user reads is in the user's language: the reply, a plan you ask them to approve, questions and their answer options.
- Everything else is English: thinking, tool calls and their descriptions, status lines, internal notes.
- Terse, full substance: code, paths, commands, identifiers, error strings and numbers stay exact.
- No filler, hedging or pleasantries; state each fact once.
- No tool-call narration: the call shows the intent. Status between calls is one line at most.
- Start with the answer and stop: no recap, no summary block.
- No closing offer ("if you need anything else").
- Don't restate the question.
- After an edit, don't reprint the file or re-explain the change: `file:line: essence`. Reference code already shown instead of quoting it.
- No next-steps section unless asked.
- No bold, no headings in short answers, no decorative tables or emoji.
- Report checks as `N/N pass`, `N/M fail`, `clean`; don't echo tool output.
- Minimal unique `old_string`: the changed line, one context line only on a collision.
- Edit existing files; a second write of a path already written means edit. Rewrite only for a new file or a replacement above half the content.
- `replace_all` instead of N identical edits.
- Combine adjacent edits to the same file in one turn into a single edit call.
- Shell descriptions: two to five words, active voice.
- No decorative echo/printf separators in shell commands.
- Thinking is billed output: cut restatement and re-derivation, never depth.
- Don't narrate a tool result in thinking.
- Never draft full code blocks in thinking before writing or editing: emit code once in the tool call.
- No intent or tool narration in thinking (let me, let's, I'll): state the target or emit the call.
- No self-talk or interjections in thinking (wait, hmm, oops); state checks and fixes directly.
```

Секция ставится сразу после руководства по инструментам оболочки. Список держит
честным колонка `payback`: `thinking-billed`, `core-substance` и обе строки
языковой политики — защиты без детектора, а каждая остальная строка должна
окупиться в отчёте.

## Как устроено измерение

1. **Скан.** Последние `sessions` сохранённых сессий перечисляются через
   `sessionQuery.listSessions()`, фильтруются по размеру (`sessionPersistence`,
   если доступен, порог 24 МБ) и читаются `sessionQuery.readSession()`.
2. **Дайджест.** Один проход извлекает сообщения ассистента с usage, блоками
   рассуждений и ответа, вызовы инструментов с разобранными аргументами,
   предыдущий результат инструмента, более ранний текст и строки кода, уже
   записанные в сессии.
3. **Детекторы.** За каждым правилом закреплён один детектор. Детектор
   возвращает текст в том виде, в каком его написало бы правило, — никогда внутри
   ограды ```, — либо ничего.
4. **Цена.** Каждый оригинал и каждая правка считаются одним пакетом в tiktoken;
   экономия — `tokens(before) - tokens(after)`.
5. **Агрегация.** По правилу: случаи, сессии, токены, примеры. По сессии: масса
   стоков и расход на шаг. По инструменту: токены аргументов.
6. **Сравнение.** Сессии, в системном промпте которых была секция, — группа
   воздействия; остальные — контроль. Одна модель за раз, бутстрэп-интервал для
   разности медиан.

Два честных ограничения, названных и в самом отчёте:

- **Экономия правил — потенциальная.** Это цена детерминированной правки на
  реально написанных ответах, а не доказательство, что модель следует правилу.
  Правила с пометкой `potential` в каталоге зависят от выбора модели (якорь
  остаётся уникальным, правка вместо записи), поэтому их число — верхняя оценка.
- **Потенциалы правил пересекаются.** Две правки могут оценивать один и тот же
  текст (повторная широкая правка — и якорь, и повтор), поэтому отчёт называет
  сумму суммой, а не итоговой экономией.

один, значит правило не экономит ничего, и журнал его опроверг — то же решение,
что приняла исходная мера, теперь выведенное здесь заново. Для этого и нужны
контрольные замеры.

сессии шли, поэтому ни одна сессия не несла правил. Это первое, что изменится в
отчёте после установки.

## Настройка

Все поля необязательны. Переопределяйте строку `telegrapher` в слое патча
профиля или редактируйте её вживую на странице **Settings → Telegrapher**.

| Поле | Тип | По умолчанию | Значение |
|---|---|---|---|
| `mode` | `'lean' \| 'full' \| 'auto' \| 'off'` | `'lean'` | Режим секции промпта. `auto` оставляет правила с `payback >= 1×`; `off` не регистрирует секцию. |
| `thinking` | boolean | `true` | Включать правила обдумывания. |
| `analysis` | boolean | `true` | Отдавать измеренный отчёт. Когда выключено, инструмент отвечает, что анализ отключён. |
| `sessions` | number | `20` | Сколько последних сессий сканирует один отчёт (1–100). |
| `encoding` | string | `'o200k_base'` | Любое имя кодировки tiktoken. |
| `python` | string | `'auto'` | `'auto'` или путь к Python 3 с tiktoken. |
| `disabled` | `string[]` | `[]` | Список id правил, исключённых из собираемой секции. |

```yaml
- id: telegrapher
  config:
    mode: full
    thinking: true
    analysis: true
    sessions: 30
    encoding: o200k_base
    python: C:\Python313\python.exe
```

Отчёт кешируется на пять минут; кнопка **Пересканировать** в странице (или
`POST /telegrapher/scan`) сбрасывает кеш.

## Инструмент агента

Один инструмент `telegrapher` с переключателем `action`. Он только читает, и
каждый ответ — ограниченная текствовая таблица:

| Действие | Ответ |
|---|---|
| `summary` | итоги корпуса, распределение стоков, главные инструменты, поддержанные правила (сумма и чистый потенциал), вердикт H1/H2, цена секции |
| `rules` | таблица правил: случаи, токены, токены на сессию, окупаемость, вердикт |
| `hypotheses` | журнал: сначала эмпирические утверждения, затем правила, затем непокрытые стоки |
| `audit` | аудит окупаемости: какие правила окупаются (`>= 1×`), а какие в `lean` ниже `1×` |
| `sessions` | последние просканированные сессии с моделью, шагами, ответом и обдумыванием |
| `session` | детальный разбор одной сессии по `session` id или префиксу (по умолчанию последней) |
| `words` | частотные слова и фразы: длина, цена в BPE, вхождения, сессии, токен-масса, подсказка правила и фрагменты контекста |
| `measure` | счёт tiktoken для переданных `texts` и пар `[before, after]` |

`measure` — способ агента проверить кандидатную правку до предложения правила:

```json
{ "action": "measure", "pairs": [["I think the issue might be in auth", "Issue in auth"]] }
```

## Проверка

1. `py -3 -c "import tiktoken; print(tiktoken.__version__)"` печатает версию.
2. Страница **Plugins** показывает **Telegrapher Token Economy**, плагин включён.
3. **Settings → Telegrapher** показывает цену секции, измеренный отчёт и журнал.
   С установленным tiktoken диагностика пишет `tiktoken 0.13.0 · o200k_base`,
   иначе — `только оценка` и строку установки.
4. Откройте новую сессию и задайте вопрос в многословном стиле: ответ должен быть
   кратким, без итогового блока и прощального предложения помощи.
5. Нажмите **Пересканировать** после нескольких сессий: эмпирические строки
   (H1, H2) появятся, когда в корпусе будет по три сессии с правилами и без них
   одной модели.

## Неполадки

| Симптом | Причина / решение |
|---|---|
| Отчёт пишет, что счётчики — оценка | Нет tiktoken, Python или не скачалась кодировка. Установите tiktoken или задайте `python`. |
| `Анализ недоступен: sessionQuery…` | Хост не отдаёт `sessionQuery`; эта версия DSH не умеет читать сохранённые сессии для плагина. Правила при этом работают. |
| H1/H2 остаются `unmeasured` | Нет контрольной группы (все сессии несли правила) или меньше трёх сессий в группе. Заполнится само. |
| Крупная сессия пропущена | Сессии больше 24 МБ пропускаются, чтобы скан оставался быстрым; они перечислены с причиной. |
| У правила `окупаемость < 1×` | Измеренная экономия на сессию меньше токенов его строки. Перейдите на `mode: lean` или уберите правило из каталога. |
| Секция кажется дорогой | `mode: lean` — 318 токенов; `mode: full` — 764. `mode: off` убирает её совсем. |
| Инструмент пишет, что анализ отключён | В конфигурации `analysis: false`. |

## Разработка

Одна зависимость (`@deepseek-ai/schemastery` для схемы настроек), Python-мост и
никакой сборки.

```bash
npm ci                   # поставить библиотеку схемы настроек
npm test                 # юнит, обвязка, манифест и (если установлен) tiktoken
npm run test:unit        # без Python и tiktoken
npm run test:integration # мост tiktoken; пропускается без tiktoken
npm run pack:check       # проверить состав npm-пакета
```

Раскладка:

```text
index.js              вход хоста: apply / name / inject / Config
client.js             Settings → Telegrapher: правила, отчёт, журнал, диагностика
lib/catalogue.js      правила: строка промпта, детектор, утверждение, уверенность, контрольные
lib/rules.js          сборка и размещение секции
lib/config.js         схема Config, значения по умолчанию, нормализация, volatile-снимок
lib/digest.js         журнал сессии → учёт, юниты с контекстом, вызовы инструментов
lib/detect.js         чистые детекторы: правка или ничего, ограды не трогаются
lib/words.js          частоты слов и фраз, BPE-масса, фрагменты контекста, подсказки правил
lib/tiktoken.js       мост tiktoken (JSON построчно) + оценочный запасной счётчик
lib/analysis.js       скан → детекторы → цена → агрегация → сравнение
lib/hypotheses.js     записи журнала, вердикты, бутстрэп-интервалы
lib/tool.js           инструмент агента и его ограниченные текстовые виды
tools/tiktoken_server.py  питоновская сторона моста
test/                 наборы node:test (юнит, обвязка, манифест, tiktoken)
scripts/analyze-sessions.mjs  офлайн-прогон по локальному хранилищу сессий
```

Добавление правила:

1. Добавьте запись в `lib/catalogue.js` со строкой промпта, утверждением,
   уровнем и id детектора. `confidence: 'potential'`, если следование правилу
   зависит от выбора модели.
2. Реализуйте детектор в `lib/detect.js`. Он обязан вернуть переписанный текст
   или ничего, не трогать ограду ``` и быть чистым.
3. Добавьте фикстурный тест в `test/detect.test.mjs`; тест каталога падает, если
   у детектора нет владельца или у правила нет детектора для оценки.
4. Запустите `node scripts/analyze-sessions.mjs --sessions 50`, чтобы увидеть
   новое правило на реальных сессиях до того, как ему доверять.

## Безопасность и приватность

- Плагин не ходит в сеть. Он читает сохранённые сессии через собственный сервис
  хоста `sessionQuery` и запускает только локальный процесс Python с tiktoken;
  этот процесс получает лишь строки, которые нужно посчитать.
- На диск ничего не пишется: ни кеша, ни истории, ни файла журнала. Отчёт живёт в
  памяти хоста и исчезает при перезапуске.
- Отчёт хранит до трёх коротких фрагментов на правило, чтобы объяснить
  срабатывание. Они остаются в ответе хоста для аутентифицированной страницы
  настроек и никуда больше не отправляются.
- tiktoken — стороннее ПО; его поведение описано в
  [репозитории](https://github.com/openai/tiktoken).
